# 미션 1-1 동료 평가 웹페이지

약 10분의 한국어 발표용 정적 페이지입니다. 발표 대본·발표자 지시문 없이 실제 구현과 검증 근거를 설명합니다. 외부 라이브러리·폰트·빌드·설치가 필요하지 않습니다.

## 열기

- 저장소를 clone한 뒤 `presentation/index.html`을 브라우저로 엽니다.
- VS Code의 파일 탐색기에서 해당 파일을 Windows 브라우저로 열어도 됩니다.
- 로컬 HTTP 실행을 원하면 프로젝트 루트에서 아래 명령을 사용합니다. 별도 로컬 서버를 생성하는 선택 사항이며 Docker 서비스는 변경하지 않습니다.

```bash
python3 -m http.server 8765 --bind 127.0.0.1 --directory presentation
```

브라우저 주소는 `http://localhost:8765`입니다. 포트가 사용 중이면 중단하고 다른 빈 포트를 선택하세요. 종료는 해당 터미널에서 Ctrl+C입니다. GitHub의 HTML 파일 화면은 소스 보기이므로 웹페이지를 자동 실행하지 않습니다. GitHub Pages는 이 작업에서 설정하지 않습니다.

## 조작

- 목차 또는 이전·다음 버튼: 화면 이동
- 방향키 ←/→: 이전·다음, Home/End: 처음·마지막
- 코드 블록에 포커스가 있으면 방향키는 코드 스크롤을 유지합니다.
- 복사 버튼은 텍스트만 복사하며 실행하지 않습니다.
- 새로고침·직접 링크: `index.html#bonus4`처럼 해당 화면 열기
- 인쇄 시 모든 화면 출력, JavaScript 비활성화 시 전체 본문 표시

## 근거와 제한

[기존 README](../README.md), [공식 원문](../mission-requirements.md), 기존 YAML·Dockerfile·공개 로그를 읽고 작성했습니다. 실제 파일 블록은 파일 내용에서 추출했습니다. 개념 예시·README 재현 안내·실제 명령 발췌를 구분합니다. SSH 성공은 사용자 터미널의 보고·출력이며 Codex 환경의 SSH 실패를 숨기지 않습니다. 자료 제작 전 HTTPS 원격 조회에서 main과 로컬 HEAD `33b0e44878c86f58a0dbfc8170868ab465c787cd` 일치를 확인했습니다. 이는 SSH 인증 재검증이 아닙니다.

웹페이지의 GitHub 링크는 공개 저장소 main의 실제 파일로 연결합니다. 인터넷이 없는 환경에서는 로컬 페이지 본문은 동작하지만 GitHub 증빙 링크는 열리지 않습니다. 과거 HTTP 200은 실습 기록이며 현재 서비스 가용성을 보장하지 않습니다. PNG 51개는 기존 증빙이며 이 페이지용 새 이미지로 만들지 않았습니다.

## 제작 후 검증

임시 Chromium 브라우저에서 11개 화면의 목차·진행 표시·이전/다음·방향키·Home/End를 확인했습니다. 모든 코드 복사 버튼의 실제 클립보드 내용 일치, 코드 영역의 방향키 스크롤 유지, 직접 파일 열기와 복사, JavaScript 없는 본문 표시, 전체 화면 인쇄를 검증했습니다. 320·375·768·1280px에서 11개 화면 모두 문서 가로 넘침이 없었습니다. 데스크톱·모바일 한글 화면도 확인했습니다.

GitHub 파일 링크와 로컬 문서 링크 경로를 확인했고 실제 파일을 표시한 코드 블록 6개는 기존 파일 내용과 일치했습니다. 기존 프로젝트 파일은 해시로 보존 여부를 비교했습니다. 테스트 도구는 저장소 밖 임시 위치에서만 사용하며 이 발표 자료 실행에 설치할 필요가 없습니다. 테스트용 이미지·스크립트는 제출 파일에 포함하지 않습니다.
